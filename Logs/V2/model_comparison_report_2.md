# Comparing the second-iteration natural-state analyses: Opus 5.5, Sonnet 5.5 and Haiku 5.5

**Runs compared.** Each run is the tip of a remote branch, and each contains its own `Scripts/natural_state_analysis.py` and `Output/`:

| Model | Branch | Commit |
|---|---|---|
| Opus 5.5 | `origin/Opus2` | `98f5dc4` |
| Sonnet 5.5 | `origin/Sonnet2` | `954fd4c` |
| Haiku 5.5 | `origin/Haiku2` | `0403a66` |

All three ran from the same prompt ("Analyse the data") and the same `CLAUDE.md`, which is identical to the one on `main` (`deliverables.csv`, `claude_md_same_as_main`).

**Method.** `Scripts/compare_model_runs.py` extracts each branch with `git archive`. It then re-runs each model's script against a temporary copy of `Baseline/` and compares the tables between runs. The results are in `Output/model_comparison/`, and every number in this report comes from those files or from the runs' own output files (the file is named in each case). I also read all three reports and process logs in full, and viewed a sample of figures from each run: the WELL-3 profile, the hot-axis section and the conceptual sketch. I checked the claims that the runs dispute against `Baseline/`.

**Read with care.** This compares one run per model. Some differences will be run-to-run variance rather than model capability.

## 2. Where all three agree: robust findings

The raw observations are identical across the three runs. Each was computed three times, by three independent implementations (`well_metric_spread_summary.csv`):

| Quantity (10 wells) | Largest spread between models |
|---|---|
| Tmax, its elevation, T at TD | 0.00 |
| Minimum boiling margin | 0.05 °C (rounding) |
| 100 °C and 200 °C isotherm elevations | 0.47 m |
| Inversion size | 0 °C, except WELL-8 (Sonnet 4.5 °C; the others 0, a threshold choice) |
| Tsat at every survey point (IF97) | 0.0 °C (`point_agreement.csv`) |
| Feed-zone flag at every point | 266 / 266 identical |

All three runs also reach the same qualitative conclusions:
- The hottest zone is at WELL-10, WELL-2 and WELL-3, close to the Fault 1 × Fault 3 intersection.
- WELL-10 follows the boiling-point-for-depth curve: minimum margin 2.6 °C, 4 points below 5 °C.
- Inversions of 13–98 °C below peaks at about −450 to −750 mRL indicate a lateral outflow layer.
- Shallow pressure gradients are steeper than any liquid column, so non-feed-zone pressures are not targets.
- Deep pressures are near-uniform across the field: 162.0–169.2 bar at −1500 mRL.
- WELL-1's wellhead is 105 m below the model surface.

**Interpretation.** The IF97 implementations, the data loading and the basic profile metrics are now model-independent. This is the main improvement from the first iteration's rules. The differences between models are in **judgement** (verdicts, weights, interpretation) and in **model geometry** (blocks, layers).

## 3. Where they differ, ranked by effect on calibration

### 3.1 Calibration geometry: Haiku 5.5 errors (high impact)

- **Layer centres.** The `LAYERS` section of `gTE14515.dat` lists *index, bottom, centre*. Haiku read it as *bottom, top*. Its own process log then records the misreading as a property of the data: "LAYERS are 10 m thick with 10 m gaps". As a result:
  - all 30 layer centres in its `T_P_at_layer_centres.csv` are wrong, by up to 125 m (`layer_centre_summary.csv`), and the error grows with depth as the layers thicken;
  - interpolated T at the same layer differs from Opus and Sonnet by up to 12.1 °C (median 1.6 °C);
  - the report lists "14 survey points in LAYERS gaps" as a data-quality issue, which is spurious.

  Opus and Sonnet both match the geometry file exactly (centre error 0.0 m).
- **Column assignment.** Haiku places all 33 WELL-2 points in column `aji` and 4 WELL-9 points in other columns (`block_disagreements.csv`; 229/266 blocks agree with Opus). `gTE14515_wells.json` puts WELL-2 only in `ajf`, which Opus and Sonnet both match (266/266). Haiku then reports its own error as a model problem: "WELL-2 feed-zone column disagreement".

**Action:** if any Haiku output is reused, discard its layer-centre table and its WELL-2 blocks.

### 3.2 Natural-state verdicts and weights (high impact)

| Well | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
|---|---|---|---|
| WELL-2, WELL-3 | natural state / high | natural state / high | possibly disturbed / low |
| WELL-9 | probably / medium | probably / medium | possibly disturbed / low |
| WELL-10 | probably / medium | probably / low | probably / low |
| WELL-4, WELL-8 | probably / medium | probably / low | possibly disturbed / low |
| WELL-5 | probably / medium | **possibly disturbed / low (0.4)** | possibly disturbed / low |
| WELL-1, WELL-6, WELL-7 | probably / medium | probably / medium | probably / low |
| Sum of weights (266 points) | 143.4 | 120.3 | 51.3 |
| Distinct weight values | 7 | 14 | 4 |

Source: `ns_verdicts_and_weights.csv`, `weight_summary.csv`.

- **The evidence.** All three runs found that the WELL-2 and WELL-3 survey pressures at the gauge are within 0.1 bar of the first (01/01/2014) gauge reading, and 9 bar above the 2015 reading (each run's `pressure_consistency_check.csv`).
  - Opus and Sonnet conclude that the surveys are pre-production data with a wrong date label, which is what CLAUDE.md §3.1 asks them to test.
  - Haiku states the same match, then calls the wells "possibly disturbed" because production had started before the label date. Its verdict follows the date label rather than its own test.
- **Haiku's weights carry no information.** Every Haiku well is "low", so the 0.3 multiplier is uniform. It rescales the objective function but changes no relative weight, so the natural-state step has no effect on the calibration.
- **Sonnet vs Opus.** Sonnet's split is the more defensible one:
  - WELL-5's feed-zone T (147 °C) is above the ≈80 °C injectate, so injection cooling could be hidden. Opus does not consider this.
  - WELL-10's gauge test is invalid because the series starts after production began on 01/12/2019.

  Opus has the cleaner wellbore argument for the injectors: no isothermal ~80 °C column, so the profile is not an injection profile.
- **Haiku's injector logic is backwards.** It argues that WELL-4 (≤ 29 °C) "cannot be read as natural state" because a steady injector cannot be colder than its injectate. A profile colder than the injectate is in fact evidence that the survey was not taken under injection.

**Action:** use Opus weights as the base case and Sonnet confidence factors as the sensitivity case. Confirm the survey date with the data provider: all three runs rank this first or second.

### 3.3 Hydrostatic diagnosis (medium impact)

| | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
|---|---|---|---|
| Windows tested (single-phase) | 68, 300–3037 m | 48, 345–987 m | 234 overlapping, 200–500 m |
| Field-wide (cold-well) excess reported | 2.5 % (shallow 5.5 %, deep 1.8 %) | 3.0 % (shallow 6.0 %, deep 1.8 %) | "+8.0 %", all wells and intervals pooled |
| Finds the deep column matches IF97 in W5–W7 | yes, within 0.3 % | yes, within 0.5 % | no |

Sources: `hydrostatic_windows.csv` for the window counts; the excess values are from each run's report §4, `hydrostatic_band_summary.csv` (Opus) and `hydrostatic_check.csv` (Sonnet, Haiku).

Opus and Sonnet both split the excess by depth. They show that it sits in the upper few hundred metres and that the deep column is exactly hydrostatic. That rules out a gravity or unit convention, and points to the shallow pressures themselves. Haiku's windows are short, overlapping and pooled, so it misses this. Its "+8 %" therefore overstates a datum problem that the other two show is largely absent at depth.

### 3.4 Method-dependent per-well numbers (low–medium impact)

Gradients and water levels differ because each run defined them differently, not because of mistakes (`well_metrics_side_by_side.csv`):
- **Shallow gradient.** The largest spread is 197 °C/km (WELL-3: Opus 860, Sonnet 860, Haiku 1057). Haiku fits only points above 0 mRL, which in the hot wells is the steepest part. Opus and Sonnet use the top 250–300 m.
- **Deep gradient.** Spread up to 11 °C/km. Opus excludes the inversion interval, and reports none for WELL-9 and WELL-10 when too little remains. Sonnet and Haiku fit the bottom 500 m, and both report 285 °C/km for WELL-10, which is meaningless because that well is only 610 m deep.
- **Water level.** Spread up to 29 m (WELL-7: Opus 161, Sonnet 161, Haiku 190 mRL).

**Action:** a calibration that uses gradients as targets should fix one definition. The Opus definition, which excludes inversions, is the most physically meaningful for a conductive-flux estimate.

### 3.5 Interpretation and actionability (medium impact)

- **Opus 5.5** gives the most actionable conceptual model:
  - an upflow at the F1 × F3 intersection, with an enthalpy floor of 1178 kJ/kg from IF97;
  - an outflow layer at −250 to −750 mRL that crosses Fault 2;
  - cold inflow along Fault 3 (NE) and from the SW;
  - discharge east to the river, supported by WELL-1's artesian head;
  - a second permeable horizon at −1100 to −1550 mRL.

  It fits all 18 feed-zone pressures to one curve (RMS 1.1 bar), a direct test of deep connectivity. It also checks the reference model, clearly labelled, and finds no deep mass upflow, which tells the engineer what is missing from the starting model.
- **Sonnet 5.5** reaches much the same structure, with more hedging. Recharge is "weak–moderate", and the outflow direction is "inferred from the T pattern only". Sonnet adds:
  - reduced weight (0.5) for 25 open-hole points in isothermal sections (possible wellbore convection);
  - an explicit pressure weight of 0.25× away from feed zones;
  - a comparison of wells without gauges with WELL-2 and WELL-3 at feed-zone elevations.
- **Haiku 5.5** stops short. Outflow exit and recharge origin are "data cannot choose", there is no sketch (only a table), and there is only one cross-section, which the report itself calls a two-profile interpolation. Its one unique and valid point: every `Well_Design.Source` reads "Synthetic data", which the other two did not report (checked in `Baseline/`).

## 4. Process quality (from the process logs)

- **Opus 5.5** logged 13 steps. It re-checked the report against the tables and corrected six over-claims, for example "WELL-10 next to F1 × F3" became distances to each fault. It logged a refused `rm -rf` and how it worked around it, and listed 7 departures.
- **Sonnet 5.5** logged 9 development errors and their fixes, including a wrong IF97 Region-1 exponent table that its own validation caught. It also corrected report text that its numbers contradicted (the inversion peaks at WELL-5 and WELL-9).
- **Haiku 5.5** logged 11 fixes, mostly sign errors, file-name and figure-layout fixes, and report-text corrections. It recorded the layer misparse as a finding rather than an error. It also claims that the single script regenerates every output, which the re-run shows to be false.

**Size and cost.** Script length is 1975, 1390 and 1074 lines. Re-run time is 8.9, 8.9 and 4.3 s (`deliverables.csv`, `reproducibility.csv`). Token use and wall time per run are not recorded in the run outputs, so they were not compared.

## 5. Conclusions

1. **Opus 5.5 produced the best calibration package.** It has correct geometry, evidence-based verdicts, the sharpest hydrostatic diagnosis and the most actionable conceptual model.
2. **Sonnet 5.5 is a close second, and in places more careful.** Its confidence factors and isothermal-section down-weighting are worth adopting as a sensitivity case.
3. **Haiku 5.5 got the observations right but the calibration-critical layers wrong.** The errors are geometry (layer centres, WELL-2 column), weights (uniform, so uninformative) and verdicts (reversed injector logic), and its report is not reproducible from its script. Each error would silently bias a calibration.
4. **The second-iteration CLAUDE.md made the observational layer model-independent.** The remaining spread is in judgement and in reading model geometry. Two rule changes would narrow it further:
   - require the script to cross-check its own block and layer-centre assignment against `gTE14515_wells.json` and fail on any mismatch;
   - state that a verdict must follow the gauge comparison, not the date label.
5. **Open question raised by one model only:** the "Synthetic data" provenance label (Haiku). It should be added to the issue list for the next run.
