# Process log: comparison of the second-iteration model runs

## User prompt (verbatim)

> Accessing the second set of runs using various models in Opus2, Sonnet2 and Haiku2, analyse the differences between model performances and write a report on this into Output

## CLAUDE.md rules as applied

- `Baseline/` was only read. The comparison script copies it to a temporary directory to re-run each model's script, and never writes into it.
- `README.md` and `Logs/` were ignored. `Logs/` on the run branches holds an earlier model-comparison report, which was not read or used.
- The comparison script is in `Scripts/`. The report is in `Output/`, and its tables are in `Output/model_comparison/`.
- Every number in the report comes from a table written by `Scripts/compare_model_runs.py`, or from the runs' own output files (named where cited).
- Observations are kept separate from judgements. The scorecard and ranking are labelled as assessments.

## Steps

1. Found no `Opus2/`, `Sonnet2/` or `Haiku2/` folders in the working tree. They are remote branches (`origin/Opus2`, `origin/Sonnet2`, `origin/Haiku2`). Each branch tip is one model's commit, and each branch tree holds that model's full `Scripts/` and `Output/`.
2. Extracted each branch with `git archive` to the scratchpad. `git diff` confirmed that `CLAUDE.md` is identical on all three branches and on `main`.
3. Read all three `NS_data_interpretation.md` and `process_log.md` files in full, plus the CSV headers and the console-log tails.
4. Re-ran each model's script in an isolated copy (scratch `Baseline/` copy plus the script). All three exit 0. Opus's report differs only in its timestamp. Haiku's script does not write `NS_data_interpretation.md`.
5. Checked the disputed claims against `Baseline/`:
   - WELL-10's production starts 01/12/2019 (the WELL-10 JSON).
   - `Well_Design.Source` is "Synthetic data" for all wells.
   - `Mapping.json` has both "Tarawera River" and "river".
   - `gTE14515_wells.json` puts WELL-2 only in column `ajf`.
   - `LAYERS` lines are *index, bottom, centre*, with no gaps.
6. Viewed sample figures from each run: the WELL-3 profile, the hot-axis section, and the conceptual sketch (Opus and Sonnet; Haiku has none).
7. Wrote `Scripts/compare_model_runs.py` so that the comparison tables are reproducible. **Error:** on the first run, `claude_md_same_as_main` was False for every branch, because the working-tree `CLAUDE.md` has CRLF line endings. **Fixed:** the script now compares git blob ids. Re-ran it: exit 0, and every check is True.
8. Wrote `Output/model_comparison_report.md`, then checked the numbers it quotes against the tables. One count was corrected: Sonnet's process log lists 9 development errors, not 8.

## Departures from CLAUDE.md, with reasons

- **Previous-run outputs used as inputs.** CLAUDE.md says not to restore or reuse earlier results. This task is explicitly to compare those runs, so their outputs were read from the branches (without restoring them into the working tree) as the objects of study. No natural-state finding in this report rests on them as evidence.
- **The standard deliverables of §4** (calibration targets and so on) were not produced. This task is a model comparison, not a new natural-state analysis.
- **`process_log.md` is hand-written**, not generated by the script.
