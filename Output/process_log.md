## 2. CLAUDE.md rules as applied

- `README.md` and `Logs/` were ignored. `Baseline/` was only read; `git status Baseline` shows no change.
- Earlier results deleted from the working tree, and those in git history, were not restored or used. The analysis started from `Baseline/`, and the script was written from scratch.
- Scripts are in `Scripts/`, and outputs are in `Output/` and `Output/figures/`. `Scripts/check_deliverables.py` was not edited.
- Scope is the natural state only. Production, injection and enthalpy records were used only for the timing test in §4.1. Field-total production (`Area_data.json`), the production and forecast set-ups and the spreadsheets are inventoried as `out_of_scope`.
- **Inventory first (§2.1).** The script classifies every file under `Baseline/` by content and collapses directories that share one role. It writes `input_inventory.csv` with 18 rows covering all 75 files.
- **Data vs reference (§2.2).**
  - Reference-model files (rock types, boundary conditions, the NS input file, the initial conditions and the set-ups) were used only for a summary labelled **[reference model]**.
  - The grid file was used only for its vertices, grid, layers, surface and wells sections.
  - The well-to-block file is the authority for block assignment.
  - The one external assumption is rock conductivity, 2.5 W/m/K. It is stated as an assumption in the report and in `analysis_parameters.csv`.
- **Thermodynamics (§4.3).** IF97 Region 4 gives Tsat and Region 1 gives density and enthalpy. The script validates both against the IF97 verification tables and against Tsat(1.01325 bar) and Tsat(100 bar), and stops if any error is above tolerance; the largest Tsat error is 0.0043 K. Tsat is blank above 220.64 bar.
- **Weights (§5).** Defaults were used without departure:
  - location weights 1.0 / 0.8 / 0.5 / 0.5 / 0.3 / 0;
  - confidence factors 1.0 / 0.75 / 0.5;
  - quality factors HIGH 1.0, MEDIUM 0.8, LOW 0.5, and `Synthetic` 0.5 because it is not a grade.
  Confidence differs between wells (2 high, 7 medium, 1 low).
- **Every report number comes from an output table.** Report numbers go through a formatter that also logs them to `report_derived_numbers.csv`; the R1 check confirms this.
- I looked at every figure after generation (§7) and fixed overlapping labels and legends.

## 3. Steps taken

1. Listed all 75 files under `Baseline/` and read `Scripts/check_deliverables.py` to learn the acceptance contract.
2. **Explored the formats** and confirmed each claim in CLAUDE.md §3:
   - **Well JSON.** List entries are strings, parsed with `ast.literal_eval`. Feed zones are labelled `m` but are mRL. Surveys are keyed by date, then by elevation string. Each well has one survey, dated 29/07/2015, and T and P at identical elevations.
   - **Grid file.** The LAYERS section is `index bottom centre`, with line 0 as the top surface (1000 mRL); it was confirmed, and the acceptance G3 check agrees. Block names are the column name plus the layer number, confirmed against the block file (e.g. `arz38` covers 260 to 240 mRL).
   - **Plain-column files.** Surveys are `value elevation`. Transients are `years since 01/01/2014` and value, with time quantised to months (k/12). Production mass flows have the opposite sign. File names `Wel10_*` are irregular.
   - **Mapping.** River entries are ragged lists of segments; faults are 2-point polylines; the lake is a filled polygon.
3. **Wrote the script**: inventory, readers, integrity checks, the JSON/plain-column cross-check, an independent point-in-polygon column check, the timing test, the target table, feed zones, layer centres, common elevations, the hydrostatic check, the well summary, the geometry check, figures and the report.
4. **First run, reviewed the tables:**
   - All 38 plain-column files match the JSON exactly.
   - Point-in-polygon agrees with the block file at 276 of 276 points.
   - The gauge test passes for WELL-2 and WELL-3, with differences of −0.1 bar.
5. **Errors found and fixed during development:**
   - **WELL-10 verdict.** The first rule called WELL-10 "possibly disturbed" because its survey-minus-gauge difference (8.0 bar) was smaller than the drawdown at the passed gauges by 2020 (14.2–15.1 bar). The gauge starts 6 years after field production, so it cannot decide. I changed the rule to use the pressure-trend test: the feed-zone residual is +1.9 bar, where a post-production survey would sit about 8–9 bar below the trend. The result is probably natural state, medium, and the open question is kept in the report.
   - **Isothermal threshold.** The first threshold, |dT/dz| < 20 °C/km, flagged WELL-4's low conductive gradient as "isothermal". I tightened it to 10 °C/km.
   - **Deep gradient.** The first version measured the interval by the span of points, which blanked WELL-2. I changed it to the literal rule (interval from the limit to TD ≥ 300 m) and added a column for the point span. The report flags WELL-2's value as weak: 2 points, 98 m apart.
   - **Above-surface flag.** The first version used the block file's top; it now uses the model surface (SURFA). No point is above the surface, because every wellhead is at or below it.
   - **Transient reference date.** A median rounded to the day gave 31/12/2013 for one file, because of the monthly quantisation. I now round to the nearest month start, and all files give 01/01/2014.
   - **Code bugs.** An indentation error, and two string literals broken by newline escapes in heredoc patches. Both were fixed.
6. **Independent review of conclusions against the tables** (§7). I tried to disprove each claim; the changes were:
   - **Conclusion 5.** The −1000 mRL pressure range included WELL-1, so the range read 114.40–120.03 bar while §5 said WELL-1 is low. I added a 2-bar grouping tolerance: 7 wells read 118.57–120.03 bar, and WELL-1 is reported separately at 114.40 bar.
   - **Conclusion 7.** It quoted "open-hole min–median" over all open windows, which include the outflow windows. It now uses the deep open windows, those whose top is at or below −1000 mRL: 0.9975–1.0211. A wrong section reference (§4.3) was corrected to §4.1.
   - **Trend equation.** The sign was inverted: the slope is negative, so the equation reads P = 32.76 − 0.0877·z.
   - **Hard-coded numbers.** "Roughly 9 bar", "several times the rounding uncertainty", "−2400 mRL" and "428 m" were replaced by computed values.
   - **Feed-zone overpressure.** I had first called positive values "physically odd". Overpressure under a cap with upflow is physical, so I reworded it, and added the excess relative to a column from the model surface: this explains most of WELL-1's +12.9 bar, because its wellhead is 105 m below the surface.
   - **Isothermal sections.** The text had attributed them generically to "internal flow or formation". I added a feed-zone-pair test, since internal flow needs an entry and an exit bracketing at least half the section. Only WELL-2's section is bracketed (feed zones 2 and 3, and the section temperature matches feed zone 3). WELL-3, 5, 6, 7 and 8 have no bracketing pair, so those sections are probably formation features. The outflow and recharge text was updated.
   - **WELL-10 two-phase text.** It said "no data above −75 mRL", which was wrong: the survey reaches 210 mRL and margins grow upward. Corrected.
   - **WELL-5 inversion.** Its location was described as "at or above the shoe, in open hole", which contradicts itself. It now reads "top behind casing, base in open hole".
   - **Outflow extent.** The claim that the outflow peak "deepens with distance" was not supported; the correlation is weak. It is now stated with its correlation coefficient. I also noted that WELL-1, east of Fault 2, shows no outflow.
   - **Reference-model comparison.** I parsed the GENER section in more detail. The MASS generators sit in the top layers at 1.048e5 J/kg, which is rain-like, and the 10 largest basal HEAT sources are centred 1782 m from WELL-10. The report now says, labelled [reference model], that the starting model has no hot mass upflow under the WELL-2–WELL-10 area.
7. Ran the final analysis and `python Scripts/check_deliverables.py --rerun`: 0 FAIL, 0 WARN.

## 6. Departures from the instructions

1. **Grid VERTICES section parsed by fixed width, not by whitespace** (§3). The section has no separators, so whitespace parsing is impossible. The other sections were parsed by whitespace. An independent point-in-polygon search on the parsed vertices reproduces the block file's column at 276 of 276 points, which validates the parse.
2. **Definitions CLAUDE.md leaves open**, chosen and recorded in `analysis_parameters.csv`:
   - isothermal = |dT/dz| < 10 °C/km between consecutive points;
   - cap base = first point where the local gradient falls below 100 °C/km;
   - regime rules, applied in order (stated in the report §3);
   - dominant feed zone = highest quality grade, then thickest, then shallowest;
   - water level = linear fit of the top 100 m of the liquid survey (P ≥ 1.5 bar), extrapolated to 1 atm;
   - gauge-test tolerance = 0.1 bar;
   - injectate temperature from enthalpy at an assumed 10 bar.
3. **Hydrostatic windows always split at the casing shoe.** A band shorter than 300 m is not tested and is logged in `hydrostatic_skipped.csv`, rather than letting a window straddle the shoe. This keeps every window in the `cased` or `open` band.
4. **"Pre-production" gauge reading.** The first gauge readings for WELL-2, WELL-3 and WELL-9 are dated 01/01/2014, the same date as the first production record. I treated them as the pre-production baseline, because the next readings are 8–11 bar lower. This is flagged as part of the survey-date data question.
5. **The report narrative contains dataset-specific wording.** For example, it names WELL-1, WELL-4, WELL-5 and WELL-8 in interpretive sentences. The computations are dataset-agnostic, but the interpretive text was written after inspecting this dataset's results. Re-running on a different dataset would regenerate every table and figure correctly, but parts of the narrative would need review.
6. **Extra columns and files beyond the standard deliverables** were added after the required leading columns, or as separate files: overpressure relative to cold columns, internal-flow test, reference heat centroid and others. The CLAUDE.md §5 table allows this.
